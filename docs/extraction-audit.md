# Extraction audit — Phase 0

**Date:** 2026-10-20
**Scope:** `/home/levi/amaterasu` at `4fba760`
**Purpose:** decide what moves into Common Ground packages, what stays in the Amaterasu adapter,
and what dies. Pairs with `spec/protocol.md` v0.1.

Baseline verified before any change: **91 web tests**, **30 Rust tests**, svelte-check clean.

---

## 1. Summary

The repo already implements the two hardest client-side pieces of Common Ground:

- data-space anchors with a four-tier resolver;
- a single write path with per-turn snapshot undo.

It does **not** implement the server-side spine that makes the protocol a protocol: op ids,
revisions, an append-only log, idempotency, capabilities, approval gates, or an audit chain.
`PLAN.md` claims op-log replay as a Phase 4 acceptance criterion, but no op-log code exists:
persistence is a last-write-wins JSON blob per symbol.

So Phase 1 is not primarily an extraction. It is the addition of the journal, followed by moving
the client pieces behind the protocol. Extraction without the journal would relocate chart code
without making any claim in `COMMON_GROUND.md` true.

## 3. What is missing (evidence)

| Protocol requirement | Evidence | Severity |
|---|---|---|
| Op envelope (`op_id`, `turn_id`, `actor`, `capability`, `rationale`, `idempotency_key`) | `packages/canvas-chart/src/schema.ts` — `Op` is a closed union of `draw/update/remove/clear/set_view/add_series/remove_series`; no envelope; ids are generated by `DocStore` | Blocker |
| Revision / total order | `server/src/workspace.rs` has only `updated_at`; no revision anywhere | Blocker |
| Append-only op log | `grep` for op log returns no app code; `workspace_docs` is `INSERT ... ON CONFLICT DO UPDATE` | Blocker |
| Idempotency | Ops carry no key; retries re-apply and create duplicate shapes | Blocker |
| Typed rejection | `OpResult = {ok, warnings[]}`; no codes, no retryability, no suggestion | High |
| Capability scoping | The agent has `chart_*: allow` for every chart; no document/op-type scope | High |
| Human approval gate | Only a prompt instruction ("destructive: only when the user asks") | High |
| Audit chain | Absent | High |
| Inverse ops | Snapshot undo only, client-side; lost on reload | High |
| Unknown-field preservation | zod objects strip unknown keys by default; violates protocol §3.2 rule 1 | Medium |
| Generic object model | `DocState` hardcodes `annotations` and `series` | Medium (chart-only v0 may defer) |
| Conformance corpus | 8 web test files, all adapter-specific | Medium |

## 4. What this means for the build order

The plan in `COMMON_GROUND.md` says Phase 1 ports the reducer. Reordered:

1. **Phase 0 (this week):** spec v0.1, this audit, protocol schemas, conformance fixtures and runner.
2. **Phase 1a (done):** journal in the Rust server — `doc_ops` table, revisions, idempotency, hash chain,
   acks. The existing bridge journals at dispatch and finalizes on the browser ack.
3. **Phase 1b (done):** extract `DocStore` and inverse computation into `packages/canvas-chart` (the
   adapter, not `canvas-core`), with the reducer and inverse tests moved and passing.
4. **Phase 1c:** capability minting and approval gate; history drawer reading the log.
5. **Phase 2:** `canvas-mcp` tool registration generated from schemas; second adapter (Weave).

The reorder matters because the journal forces the spec to be real. Extracting first would preserve
today's client-only semantics under new package names.

## 5. Risks found during the audit

| Risk | Detail | Mitigation |
|---|---|---|
| Browser is canonical today | Ops are applied in the browser and never leaves a durable trail; two tabs can diverge | Phase 1a makes the server the log of record; adapter acks include inverses |
| `PLAN.md` overstates completion | Op-log replay and deterministic reload are listed as done-when criteria but not implemented | Correct `PLAN.md` §7 Phase 4 and README claims |
| Reducer move is not mechanical | `DocStore` imports chart schemas directly and hardcodes `annotations`/`series` | Make it generic over a `DomainSchema`; keep the 22 tests as the gate |
| zod strips unknown fields | Forward compatibility rule would be silently violated | Envelope schemas use loose objects; payload schemas stay strict |
| Turn grouping depends on message ids | `bridge-wiring.ts` commits a turn on `session.execution.succeeded`; a dropped browser leaves a turn open | Server-side turn records plus a timeout that closes abandoned turns |
| Ops per batch are chart-shaped | `chart_draw` loops and issues one op per shape, so "one tool call" is N round trips | Batch in the envelope; keep partial application |

## 6. Open items for Phase 1

1. `doc_id` scheme: opaque ULID plus metadata row `(doc_id, symbol, interval, adjustment)`. Do not
   encode vendor keys in ids.
2. Whether `chart.view.set` belongs in the audit log (spec v0 says yes, without a revision bump).
3. How the adapter reports a *partially* successful undo turn to the UI.
4. Whether to keep `workspace_docs` as a snapshot cache or delete it in favour of log replay once
   p95 replay time is measured.
5. Package naming: `@common-ground/canvas-core` vs `@common-ground/core`. Decide before publishing;
   irrelevant to imports inside this repo.
